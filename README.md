**The Rust SDK for Diesis**

Typed alloy bindings for every public Diesis system contract, plus the fixed
addresses and chain data you need to reach them. Each contract is an
[alloy](https://alloy.rs) `sol!` contract, so calls, events, and errors work
with your existing providers and signers.

Chain ID `1980` · Token **DS** · Bindings **alloy 2.5** · Rust **1.95+**

_Greek δίεσις: the smallest interval in music.<br>Diesis aims for the smallest interval between blocks._

</div>

---

## Why this SDK

Diesis builds trading, fee sponsorship, names, staking, and private transfers
into the chain itself, behind system contracts at fixed addresses. This crate
gives a Rust service or bot those addresses and a typed binding for each
contract, so you don't copy ABIs or signatures by hand.

- alloy `sol!` bindings for 29 public contracts, generated by abi-typegen from
  the compiled Solidity. Each one has an RPC instance type, call, event, and
  error types with their selectors, named structs for tuples, and the JSON ABI.
  The types derive `serde`.
- Every system contract and precompile address as an `alloy::primitives::Address`
  constant.
- Mainnet and testnet definitions with chain ID, native currency, and default
  RPC and explorer URLs.
- Addresses and chains are generated from the same `canonical.json` that the
  [TypeScript SDK](https://github.com/0xDiesis/diesis-js) and
  [Python SDK](https://github.com/0xDiesis/diesis-py) test against.

The crate depends on `alloy` (with the `sol-types`, `contract`, `json-abi`, and
`serde` features) and `serde`. Turn on the alloy features you need for
transports and signing in your own `Cargo.toml`.

## Install

The crate is not on crates.io yet. Add it from GitHub with authenticated Git
access, and pin a commit so builds stay reproducible:

```toml
[dependencies]
diesis = { git = "https://github.com/0xDiesis/diesis-rs", rev = "<commit>" }
alloy = { version = "2.5", features = ["provider-http", "signer-local"] }
```

The package is named `diesis`. You import it as `diesis`.

## Connect

**In short.** You make a provider that talks to a Diesis node. Add a signer
when you want to send transactions.

**Details.** `diesis::chains::DIESIS` and `DIESIS_TESTNET` carry the chain ID,
native currency, and default RPC URL. Pass the RPC URL to alloy's
`ProviderBuilder`. Adding a wallet makes the provider sign and fill
transactions for you.

```rust,no_run
use alloy::providers::{Provider, ProviderBuilder};
use alloy::signers::local::PrivateKeySigner;
use diesis::chains::DIESIS_TESTNET;

async fn connect() -> Result<(), Box<dyn std::error::Error>> {
    let provider = ProviderBuilder::new().connect_http(DIESIS_TESTNET.rpc_url.parse()?);
    assert_eq!(provider.get_chain_id().await?, DIESIS_TESTNET.id);

    let signer: PrivateKeySigner = "0x...".parse()?;
    let wallet = ProviderBuilder::new()
        .wallet(signer)
        .connect_http(DIESIS_TESTNET.rpc_url.parse()?);
    let _ = wallet.get_block_number().await?;
    Ok(())
}
```

| Network        | Chain ID | Constant                         |
| -------------- | -------- | -------------------------------- |
| Diesis Mainnet | 1980     | `diesis::chains::DIESIS`         |
| Diesis Testnet | 19803    | `diesis::chains::DIESIS_TESTNET` |

`diesis::Chain::by_id(19803)` finds a chain from an ID you got at runtime.

## Read a value

**In short.** You bind a system contract at its fixed address and call one of
its view functions.

**Details.** Each binding in `diesis::bindings` has a `new` function that takes
an address and a provider. The instance has one method per Solidity function,
named as in Solidity, with typed arguments. `.call()` runs an `eth_call` and
decodes the result. A function with one return value gives you that value, and
one with several gives you a struct with a field for each.

```rust,no_run
use alloy::primitives::U256;
use alloy::providers::ProviderBuilder;
use diesis::bindings::DiesisStaking;
use diesis::{chains, contracts};

async fn read_rewards() -> Result<(), Box<dyn std::error::Error>> {
    let provider = ProviderBuilder::new().connect_http(chains::DIESIS.rpc_url.parse()?);
    let staking = DiesisStaking::new(contracts::STAKING.address, &provider);

    let rewards: U256 = staking.unclaimedRewards(U256::from(42)).call().await?;
    println!("unclaimed rewards: {rewards}");
    Ok(())
}
```

## Send a transaction

**In short.** You sign a call to a system contract with your key and send it.
The wallet provider fills in the nonce, gas, and fees.

**Details.** Build the call on a contract instance that uses a wallet
provider, then `.send()` it. Staking is payable: the DS you attach with
`.value()` becomes the stake. `get_receipt` waits for the transaction to land.

```rust,no_run
use alloy::primitives::{utils::parse_ether, U256};
use alloy::providers::ProviderBuilder;
use alloy::signers::local::PrivateKeySigner;
use diesis::bindings::DiesisStaking;
use diesis::{chains, contracts};

async fn stake() -> Result<(), Box<dyn std::error::Error>> {
    let signer: PrivateKeySigner = "0x...".parse()?;
    let provider = ProviderBuilder::new()
        .wallet(signer)
        .connect_http(chains::DIESIS.rpc_url.parse()?);
    let staking = DiesisStaking::new(contracts::STAKING.address, &provider);

    let receipt = staking
        .stake(U256::from(1))
        .value(parse_ether("100")?)
        .send()
        .await?
        .get_receipt()
        .await?;
    println!("staked in {}", receipt.transaction_hash);
    Ok(())
}
```

## Use the generated types

**In short.** Each contract module holds the call, return, event, error, and
struct types that alloy generates, with their selectors, so you can encode,
decode, and log them without a provider.

**Details.** Names follow alloy's `sol!` rules, inside a module named after the
contract: `DiesisStaking::stakeCall` for a call, `IDiesisSpotBook::getBestAskReturn`
for a multi-value return, `DiesisStaking::Staked` for an event, and
`DiesisStaking::DiesisStakingErrors` for the error enum. Overloaded functions
get a numbered suffix, such as `safeTransferFrom_0Call`. Fields keep their
Solidity names. Calls carry `SIGNATURE` and `SELECTOR`, events carry
`SIGNATURE_HASH`, and every type derives `serde`. Each contract's JSON ABI is
a string constant in its module, such as
`diesis::bindings::diesis_staking::DIESIS_STAKING_ABI`.

```rust
use alloy::primitives::{address, U256};
use alloy::sol_types::{SolCall, SolEvent};
use diesis::bindings::DiesisStaking;

assert_eq!(DiesisStaking::stakeCall::SIGNATURE, "stake(uint256)");
let call = DiesisStaking::stakeCall { toValidatorId: U256::from(1) };
let data = call.abi_encode();
assert_eq!(data[..4], DiesisStaking::stakeCall::SELECTOR);

let event = DiesisStaking::Staked {
    delegator: address!("0x0000000000000000000000000000000000000001"),
    toValidatorId: U256::from(1),
    tokenId: U256::from(42),
    amount: U256::from(100),
};
let log = event.encode_log_data();
assert_eq!(log.topics()[0], DiesisStaking::Staked::SIGNATURE_HASH);
let json = serde_json::to_string(&event).unwrap();
assert!(json.contains("\"tokenId\":\"0x2a\""));
```

## Addresses and contract table

**In short.** Diesis system contracts live at fixed addresses that start with
`0xD1E515`. The crate has all of them, plus a table of the public contracts
with their names and keys.

**Details.** `diesis::addresses` has a constant for every entry in
`canonical.json`, and `diesis::address("DIESIS_STAKING")` looks one up by name.
`diesis::contracts` pairs each of the 28 public contracts that have a fixed
address with its Solidity name, address, and JSON ABI, using the same keys as
the TypeScript SDK's `diesisContracts`. The `name` is also the name of the
binding in `diesis::bindings`. `IValidatorShare` has bindings but no table
entry, because each validator has its own share contract.

```rust
use diesis::{addresses, contracts, Contract};

assert_eq!(contracts::STAKING.address, addresses::DIESIS_STAKING);
assert_eq!(contracts::SPOT_BOOK.key, "spotBook");
assert_eq!(contracts::SPOT_BOOK.name, "IDiesisSpotBook");
assert!(contracts::SPOT_BOOK.abi.starts_with('['));

let staking = Contract::by_key("staking").unwrap();
assert_eq!(Contract::by_address(staking.address), Some(staking));

for contract in contracts::ALL {
    println!("{:<18} {:<26} {}", contract.key, contract.name, contract.address);
}
```

`diesis::CANONICAL_JSON` is the vendored `canonical.json` as a string, for
tools that want the raw data.

## Regenerate

**In short.** Generated code comes from the contracts repo and the TypeScript
SDK's `canonical.json`. One script rebuilds it, and the same script checks that
nothing is stale.

**Details.** `scripts/generate.py` needs Python 3 and nothing else. It runs
abi-typegen's `rust` target (0.8.0 or newer) over the compiled contracts,
writes its output, including `mod.rs`, to `src/generated/bindings/`, copies `../diesis-js/canonical.json` into the repo,
and writes the addresses, chains, and contract table from it. `--check`
rebuilds into a temporary directory and fails if any generated file or
`canonical.json` differs from what is committed.

```bash
python3 scripts/generate.py          # regenerate everything
python3 scripts/generate.py --check  # fail if anything is out of date
```

The contracts checkout defaults to `../../diesis-core/diesis/contracts` and must have its
`out/` artifacts built. Set `DIESIS_CONTRACTS_DIR` to use another checkout,
`ABI_TYPEGEN` to use another abi-typegen binary, and `DIESIS_CANONICAL_JSON`
to read `canonical.json` from somewhere else. Don't edit files under
`src/generated/` by hand.

## Develop

```bash
cargo test                                   # unit, integration, and README tests
cargo clippy --all-targets -- -D warnings
cargo fmt --check
```

The binding tests parse each embedded ABI with alloy's `JsonAbi` and check
that it has the same functions, events, and errors as the `sol!` binding. They
also compare the embedded ABIs with the artifacts in `../../diesis-core/diesis/contracts/out`,
and skip that comparison when the artifacts are not present.
